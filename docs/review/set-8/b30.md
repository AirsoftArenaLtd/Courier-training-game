# B-30: cab narration

18 October 2026. Branch `codex/b30-cab-narration`, from pilot `951ef36`.

Cab controls now share a two-slot speech queue in the owned accessibility adapter. P selection,
gear confirmation, switches and actual mirror-check changes are spoken. Ordinary hints start at
least 1.5 seconds apart, coalesce to the latest change and never cancel existing speech. The rear
camera reads only changes between clear, within three meters, within one meter and stop, rather
than every fractional distance. Leaving reverse drops pending camera speech.

The immediate stop warning is the safety exception to the ordinary 1.5-second spacing: it can
replace this adapter's own hint. It never cancels a panel or another speech reader. A panel owns
speech until it finishes or the trainee closes it. Opening panels discards stale cab hints.
Everything uses the existing narration option, translation function, language and audio volume.
Speech state lives only on the scene; scoring, checkpoints and shared accessibility files are unchanged.

The original `test/tools/narration-probe.js` assigns to the read-only `window.speechSynthesis`
property. Chromium silently ignores that assignment (`assignmentWorked: false`, native object
retained). Its replacement utterance constructor then cannot be passed to native speech, and
the shared reader catches the error. This explains its zero capture; existing `message()` actions
already requested speech. The new owned browser test defines the property explicitly and records
the utterances, including the new live mirror and rear-camera announcements. Claude's probe is unchanged.

## Evidence

- [Speech capture](b30/narration.json): 18 browser assertions. Six rapid P selections produce two
  utterances, 1.528 seconds apart; reverse, headlights, drive and the actual left-mirror dwell are
  captured. A held panel remains uninterrupted for 1.9 seconds despite a stop becoming current.
  Stop and both near bands are heard. The four-second real-key reverse reaches -1.7 m/s and
  produces one utterance. Switching narration off silences actions and distance changes.
- Nine deterministic narration tests cover coalescing, stable-message deduplication, external
  ownership, immediate stop, all four bands, pending-band disposal, mirror and light changes,
  missing speech, settings off, translation, volume and no saved model state.
- [Node suite results](b30/node.json): 31 suites pass, including mission, world, workday, resume,
  save size and i18n. The new credits check also passes (two assertions).
- [Narrated cab](b30/narrated-cab.png) and [stop warning](b30/stop-warning.png), Low at 1280×720
  with larger text, colour filtering and reduced motion enabled. There is no visual layout change.
- The existing keyboard workday passes all 145 browser assertions. The Low cab/three-mirror
  [gate](b30/low.json) and loaded [reverse peak](b30/rear-low.json) pass at a combined maximum of
  **52 calls, 2,172 triangles, two textures, 3,557,376 attachment bytes and 2,557,622 estimated
  Phaser texture bytes**. Larger text, colour filtering and reduced motion are enabled.
  [High](b30/high.json) also passes separately (88 calls / 67,910 triangles in the cab).
  No rendering resource or pass was added. SwiftShader frame rates are software-only diagnostics;
  native Intel acceptance remains the existing O-1 owner check.

Reproduce with `QA_BASE=http://127.0.0.1:8330 node test/fpnarrationbrowser.js` and
`node test/fpnarration.js`. The browser uses deterministic speech capture, so it verifies requests
and scheduling, not the quality or availability of an installed human-language voice.

The gate commands use `QA_PROTOTYPE_ONLY=1 QA_TAG=b30 QA_GFX=low QA_A11Y=large,colour,reduced`
with `QA_VIEWS=cab,mirror,mirrorRight,mirrorInterior`; the separate reverse sample uses
`QA_TAG=b30-rear QA_VIEWS=laterrearpeak`. All run `node test/fpbench.js` against `QA_BASE`.

# Night-run component draft

The agreed four catalogue checks are implemented in `fpnightlesson.proposed.js`: light inspection before moving, headlight use, the live three-second following gap, and one route-following efficiency check. Failure observations dominate later positives, scoring maxima and wording come from the catalogue, and local observations are bounded. A complete result requires actual travel, a real lead-traffic encounter, night driving and the whole stopped van in the painted finish bay.

Six component cases pass. They use the actual mission, inspection, motor, traffic, night and following controllers, with a workday report sink that throws. Parking poses are fixtures for component gate tests. Late inspection/headlight corrections preserve the earlier failures; wrong turns survive later credit; timeout gives zero while retaining observations; overflow cannot complete.

**This is a draft, not a registered or scene-loaded scenario.** No index, shared registry, launcher or saved workday field changes. Scene controls, brief, native walking/inspection/drive/finish, localized layouts, graphics measurements and optional-launcher acceptance remain. The initial component failure was a test fixture that drove from its pre-positioned finish bay; the corrected test uses an independent fresh model for its positive drive. The initial failed log is retained.
